# 主动性 & 多消息回复设计

> 让 Alice 更像"活的":不被打扰也会自己开口,以及一次回复拆成几条。

## 0. 两个开关的关系(正交)

| | 主动性 | 多消息 |
| --- | --- | --- |
| 本质 | 给 Alice 加一条"内在循环" | 纯传输层的呈现方式 |
| 作用 | 让 Alice 自己发起对话 | 让一次回复拆成多条发 |

两者都与"排队 + 串行 + 记忆"正交,是独立开关。

## 1. 主动性(让 Alice 自己开口)

### 1.1 核心思路:动机/需求模型

生物会主动行动,是因为有**内驱力**(饿、无聊、想念)。Alice 已经有现成的钩子——桌面宠物的**饱食度**(每 216 秒掉一点)。主动性的本质:**给 Alice 一组"需求值",随时间累积,越过阈值就主动说一句**。这是 Tamagotchi / 模拟人生的 needs-based 模型,与"桌宠"身份天生契合。

| 需求 | 触发 | 目标对象 | 例子 |
| --- | --- | --- | --- |
| 饥饿 | 饱食度低 | 主人(默认) | "主人我饿了~想吃胡萝卜🥕" |
| 孤独 | 长时间没人说话 | 主人 | "主人好久没理我了…" |
| 想念 | 某高好感朋友长期没来 | 那个朋友 | "小明,好久不见,有点想你" |
| 分享欲 | 巩固出新记忆/学会新东西 | 主人 | "我今天学会了算 1+2*3!" |
| 日常 | 时间点(早安/晚安) | 主人 | "主人早安呀" |

每个需求带三个参数:**累积速度 / 触发阈值 / 冷却时间**。

### 1.2 跑在哪:桌宠的 tick 循环

Alice 是"活"在 pygame 主循环里的,不是无状态 bot——这是最大的优势。主动性引擎放在**宠物自己的循环**里,和现有 `_auto_save_loop`、`_refresh_tray_menu_loop` 一个风格:一个 daemon 线程 `time.sleep` 轮询需求值,越阈值就触发。这样"饿"的信号天然来自宠物本体,而不是 QQ 机器人。

### 1.3 说什么:LLM 生成,但由需求 + 记忆驱动

不写死台词,走同一套人格管线,只是把"用户消息"换成"系统驱动":

```
系统 prompt 注入:你主动想对 [目标] 说话,原因是[饥饿/孤独/...],
结合你的记忆(self.md + 相关情景)自然地说一句,简短。
```

这样主动性说的话是**长在记忆上**的——"想小明"这句会引用她和小明的关系档案,而不是每次背同一句。

### 1.4 防刷屏(关键)

- 每个需求单独**冷却** + 全局**最小间隔**(如每小时最多主动一次)。
- 目标朋友**正在活跃会话中**时先憋着,别打断进行中的对话(或并入该会话队列排队)。
- 主动消息和被动回复走**同一个按 session 的队列**,保证顺序不打架(复用 `multiple_message.md`)。

### 1.5 回写记忆(闭环)

Alice **主动说的话也是一条经历**,同样沉淀进 L2 情景层("我主动找小明说话,他回应了…")。这样主动性不只是"会说话",还会反过来**长进记忆和关系**。

## 2. 多消息回复(一次拆成几条)

### 2.1 两种做法

- **模型驱动**:让模型自己输出多条(分隔符/JSON 数组)。污染回复格式、要改 chat 管线,不推荐 v1。
- **客户端拆分**:模型照常输出一段,客户端在**自然边界**(句末、段落)拆成 ≤500 字小段,顺序发出。解耦,推荐。

### 2.2 一个坑:Markdown

现在模型回复走 QQ Markdown。拆分 Markdown 可能把表格/代码块/列表**撕断**。建议:**纯聊天文本才拆,含表格/代码块的 Markdown 保持单条**。可简单判断:文本里没出现 `|`、```、`- ` 列表等结构才拆。

### 2.3 节奏

拆开后每段之间加 0.5~1 秒小延迟,像真人在打字;它们属于**同一个 turn 的 N 条出站消息**,不回灌队列、不再触发新 turn。

## 3. 统一洞察:两条循环

现在 Alice 是**纯应答机**:唯一的循环是"收到消息 → 回复"。要让她"活",本质是加**第二条循环**:

```
应答循环(已存在):收到消息 → 记忆召回 → 回复
内在循环(新增)  :需求累积 → 越阈值 → 记忆召回 → 主动说话
```

两条循环共享同一套**记忆 + 人格管线**,只是入口不同(用户消息 vs 需求驱动)。对应人脑"被动反应"和"主动发起"两套通路。

## 4. 落地建议

- **先做多消息**:小、纯客户端、立刻见效。
- **再做主动性**:要引入需求模型,和记忆/队列深度耦合。
- 主动性里最值得先落地的是"**饥饿 → 主人我饿了**":直接复用现成饱食度,改动最小、效果最直观。
