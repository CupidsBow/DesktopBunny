# Alice 记忆模块设计

> 参照 Claude Code 的记忆系统,为"作为智能生物慢慢成长的 Alice"设计的一套记忆架构。

## 0. 设计前提(三条已裁决的决定)

1. **会话标识 = QQ 号(session_id)** ✅ 保留,但职责从"隔离记忆"降级为"标记这是哪个朋友 + 定位当前工作窗口"。
2. **统一记忆,不分库** ✅ 所有朋友的经历存进 Alice 的**同一个**大脑,来源朋友只作为每条记忆的一个字段。这符合"一个人一个脑子",更贴近人的记忆。
3. **人格从记忆涌现** ⚠️ 纠正为:**薄核心种子(身份 + 气质 + 边界)+ 人格内容从记忆长**。详见下节。

## 1. 人格形成的生物学模型(为什么不全靠记忆推导)

人格不是一张白纸靠经历长出来的,分两层:

- **先天气质(temperament)**:天生的反应倾向(活跃度、亲和性、情绪基线),不是学来的。
- **后天性格(traits)**:由经历、强化、自我叙事**蒸馏**出来的稳定特质。

因此"完全不给 system prompt、让 Alice 从零记忆推导人格"是脆弱的:早期记忆为空 → 没有人格;巩固不好 → 人格漂移。

**正确目标**:把 system prompt 从"人设卡"缩成"基因种子",人设内容 100% 从记忆长。即 system prompt 只保留三样**不可从记忆推导**的东西:

1. 身份(我是 Alice,住在主人电脑桌面上的兔兔)
2. 气质基线(活泼、亲昵、粘人)
3. 行为边界(能用哪些工具、不能做什么)

## 2. 分层记忆架构

| 层 | 对应人的记忆 | 对应 Claude Code | 生命周期 | 内容 |
| --- | --- | --- | --- | --- |
| L0 核心 | 基因/气质 | managed 层 CLAUDE.md | 写死,不变 | 身份 + 气质基线 + 边界 |
| L1 工作记忆 | 工作记忆 | 上下文窗口 + 压缩 | 每会话,内存 | 当前对话最近 N 轮 |
| L2 情景记忆 | 情景记忆 | memory 文件(一条一文件) | 长期,落盘 | 具体事件:谁、何时、发生了什么、感受 |
| L3 语义记忆 | 语义记忆 | "learning"(feedback/project) | 长期,落盘 | 蒸馏后的稳定知识:自我形象、朋友档案、偏好 |

### L0 核心(常驻,极小)

写死在代码里,不是文件。唯一"不是记忆"的部分,像人的基因。

### L1 工作记忆(短期)

- 每个会话一个**滚动窗口**,保留最近 N 轮**原文**。
- 窗口快超预算时**不是丢弃**,而是把最老部分**压缩成摘要**写进 L2 情景记忆,窗口顶部保留"会话摘要"继续。对应 Claude Code 的上下文压缩。

### L2 情景记忆(长期,落盘)

每次重要交互沉淀成一条独立记录,带 frontmatter:

```markdown
---
name: 2026-10-20-小明-想学编程
description: 小明说自己想学编程,让 Alice 推荐 Python 入门
metadata:
  type: episodic
  source: qq:123456       # 来源朋友(统一存,打来源标)
  time: 2026-10-20T21:03
  valence: 0.6            # 情绪价:-1.0(极负面)~+1.0(极正面)
  emotion: 开心            # 情绪标签(可选)
  arousal: 0.4            # 唤醒度/强度 0~1(可选)
---
<事件正文>
```

情感字段的作用详见 §6。

### L3 语义记忆(长期,落盘,人格住这里)

从 L2 蒸馏出的稳定知识,按主题分文件:

- `self.md` —— 自我形象(我是谁、我喜欢的、我常说的话)。**常驻且小**,是人格的锚。
- `friends/<qq号>.md` —— 每个朋友的关系档案。
- `preferences.md` —— 通用偏好/口头禅/习惯。

## 3. 存储目录

```
memory/                     # Alice 的"大脑"
├── MEMORY.md               # 总索引:一行行摘要,常驻,200行/25KB 预算
├── self.md                 # 自我形象,常驻,小
├── friends/
│   └── 123456.md           # 朋友档案,按需加载
└── episodes/
    └── 2026-10-20-xxx.md   # 单条情景,按需加载
```

## 4. 两个核心机制(搬自 Claude Code)

### 4.1 索引与内容分离 + LLM 召回

每轮回复前跑一次召回:让模型扫 `MEMORY.md` 里一行行 `description`,挑**最多 5 条**最相关的情景 + 相关朋友档案,连同常驻 `self.md` 注入。

- 不向量化、不做全文检索,靠**一行描述做相关性匹配**。
- 常驻内容(索引 + self)严格限量,详情按需加载。
- 情绪强度高的记忆更易被想起(recall bias,见 §6.5)。

### 4.2 巩固(consolidation)—— 人格生长引擎

后台周期性地把 L2 情景蒸馏进 L3 语义:

- 多次出现/被强化的 → 更新进 `self.md` / 朋友档案。
- 原则:**强化现有 > 新建矛盾**,证据不足不动(防人格漂移),有旧文件就更新、不重复建。
- 情绪强度高的经历优先巩固(见 §6.5)。

这是"睡眠巩固"隐喻:经历 → 稳定自我认知。

## 5. 完整流程

```
收到朋友(QQ 123456)的消息:
1. 取该会话的 L1 工作窗口
2. 召回:扫 MEMORY.md → ≤5 条相关情景 + 朋友档案 + self.md(常驻)
3. 组装:core + self + 朋友档案(含关系/态度) + 当下心情 + 相关情景 + 工作窗口 + 当前消息
4. 模型回复(可用工具)
5. 窗口追加;超预算 → 压缩最老部分,摘要写进 L2 情景层
6. 周期巩固:L2 情景 → L3 语义(人格慢慢长大),巩固时顺带给事件打情感分(§6.6)
```

## 6. 情感子系统(affect)

让 Alice 从"能聊天"变成"有感情、会亲疏有别、会记仇也会原谅"。核心思想:**每条记忆不只记"发生了什么",还记"当时的我是什么感受";感受随时间的加权累积,长成感情。**

### 6.1 情感的双重表示

维度化(用来算)与类别化(用来表达)互补:

| 字段 | 类型 | 范围 | 用途 |
| --- | --- | --- | --- |
| valence | float | -1.0 ~ +1.0 | 好坏程度,用于聚合(态度/心情) |
| emotion | str | 开心/委屈/生气/... | 语义标签,用于表达语气 |
| arousal | float | 0 ~ 1 | 强度,用于 salience(回忆/巩固优先级) |

- valence 给聚合、emotion 给表达、arousal 给"强度"。
- **情感痕迹(存在记忆上)存了就不变**,那是"过去的感受";而**态度与心情是派生值,实时重算**。

### 6.2 存储位置

- **L2 情景记忆**:每条带 valence(+ emotion/arousal),是"情感痕迹"。
- **派生值(不存盘,实时算)**:
  - **对朋友的态度(attitude)** —— 该朋友所有情景的 valence 加权聚合。
  - **当下心情(mood)** —— 最近一段时间所有情景的 valence 聚合,衰减快。

### 6.3 态度:亲疏的来源

```
attitude(friend) = Σ valence_i × w_i / Σ w_i
w_i = intensity_i × decay(age_i)          # 越近权重越大
confidence       = Σ w_i                   # 证据量:记忆越多越可信
```

- **态度连续值 → 离散关系等级**:陌生 / 认识 / 熟络 / 亲近 / 亲密(阈值切分)。
- **置信度**决定"稳不稳":只有一次好评(低置信)不算"关系好",很多次(高置信)才算。
- **时间衰减**给出"记仇也会原谅":一次负事件拉低态度,后续没再发生 → 随时间回暖;半衰期可调。

### 6.4 心情:当下的语气

- 由**最近窗口**(如近几小时)的情景 valence 聚合,衰减半衰期**远短于态度**(心情是短时的)。
- 每次回复注入一句:`你现在的心情: 开心(0.4)` → 直接影响 Alice 语气。
- 与态度分离:对某人不爽,但整体心情可以好;反之亦然。

### 6.5 情绪如何影响回忆与巩固(双向)

**回忆偏向(recall bias)**:
- salience = |valence|(可 × arousal)高的记忆更易被召回——情绪事件记得牢(真实记忆效应)。
- 心境一致(可选):心情好时偏向召回正面记忆。

**巩固优先级**:
- salience 高的事件优先蒸馏进 L3 语义——刻骨铭心才改变"我是谁"。
- 态度跨过关系等级阈值时,更新 `friends/<qq号>.md` 的"关系"字段。

### 6.6 谁来打分

不额外接情感模型,**由 DeepSeek 在巩固时顺带打**:读事件正文 → 输出 `{valence, emotion, arousal}`。零额外成本,且与事件是同一套理解。

### 6.7 一个完整例子

```
1. 小明第一次私聊,聊得很开心
   → episode 存下 valence +0.6 → 对小明态度 = 0.6(置信度低)
2. 之后小明又来找过几次,都很愉快
   → 态度累积到 +0.8,且置信度升高 → 关系等级升到"亲近"
   → 下次见面注入"你和 小明 很亲近" → Alice 语气更熟络
3. 有天小明说了句气话
   → episode valence -0.5 → 态度从 0.8 掉到 0.5
   → 当天 Alice 对小明明显冷淡(心情也受影响)
4. 之后小明道歉、恢复友好
   → 态度随时间慢慢涨回 → 关系修复
```

### 6.8 调参(关键)

| 参数 | 建议初值 | 说明 |
| --- | --- | --- |
| attitude 半衰期 | 7 天 | 亲疏的记忆尺度 |
| mood 半衰期 | 2 小时 | 心情的时效 |
| 关系等级阈值 | -1 / 0 / 0.3 / 0.6 | 陌生 → 亲密 |
| 心情窗口 | 近 4 小时 | mood 聚合范围 |

调好半衰期与置信度,否则要么一辈子记仇,要么秒忘。

### 6.9 诚实的边界

valence 不是真感情——Alice 没有生理状态。它是一套计算代理:**态度的加权累积 + 时间衰减 + 回忆偏向 + 语气调制**,合起来"看起来像有感情"。设计上保证三点:情感痕迹只存不删、态度与心情实时重算、负情绪可随时间恢复。

## 7. 落地顺序(渐进)

1. **Phase 1**:人设 system prompt 瘦身为 L0 核心种子;工作记忆改成"窗口 + 压缩摘要"(替换滑窗)。
2. **Phase 2**:落盘存储 + MEMORY.md 索引 + 召回 side-query(情景 + 朋友档案 + self)。
3. **Phase 3**:巩固循环(情景 → 语义)+ 情感子系统(valence/态度/心情),人格开始"生长"。
